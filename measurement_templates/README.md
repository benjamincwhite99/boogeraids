# Optional intervention logs

Copy this folder to `output/measurement` and complete the CSVs, keeping their headers. The normal `python3 run_all.py` command reads them when building the dashboard. `python3 dashboard.py` also refreshes it. Files are optional; empty/missing files show awaiting measurement. Invalid input stops the build before replacing the dashboard, so an existing HTML may still show an older run.

Use codes, not names or personal disclosures. Never enter real caller records. Keep generated logs local. One sessions row represents one actual event, with a unique stable event_id and ISO date (YYYY-MM-DD). Do not substitute historical date/county groups. Use consistent codes for audience, venue, room/equipment configuration, facilitator and all versions. Date ties sort by event_id; use IDs that preserve delivery order on the same date. If ordering is uncertain, resolve it before interpreting a rolling window.

Attendance and counts are nonnegative integers. Planned minutes must be positive; minutes lost cannot exceed actual minutes. Record non-overlapping lost teaching time. Set essential_inaccessible, factual_error, missing_core_explanation and access_requirement to yes or no even if remedied; the action register records the resolution. Incident categories use `|` when multiple types occur (for example `AV|external interruption`). Keep category spelling consistent. Suggested categories: AV, audibility, external interruption, room/privacy, registration/schedule, access. Food requests are not teaching incidents.

Assessment rows are unique by event_id, item_id, key_version and timepoint (before/after). Offered = answered + omitted; correct ≤ answered; offered ≤ attendance. Include “not sure” among answered, scored according to the approved key. matched is optional and cannot exceed answered. Aggregate rows cannot establish paired change; this dashboard does not calculate it.

Adaptation windows use the latest sessions within the same audience, curriculum, FAQ, scenario, pilot condition, item and key version. The latest three must each meet the minimum answered count; low-count recent sessions are not skipped. Different facilitators may still differ; staff must assess comparability. Only after-training checks trigger adaptation review. Agree missingness tolerance before a retention decision. No automatic retention/success decision is calculated.

Action buckets are delivery, adaptation or structural. Use `|` for related event_ids. Supply an evidence reference, threshold version, trigger date and owner role. decision is blank, `in progress` or `reviewed`; reviewed requires an action_taken and review_date. Calculated flags remain visible independently of staff reviews. Maintain one current row per action; preserve earlier register versions separately for an audit trail.

thresholds.json contains proposed rules. Version changes and document why they were made before using a new policy. maximum_omission_fraction is initially null (not agreed). No threshold is validated by the historical survey. The dashboard uses the larger of the policy minimum and the survey small-group threshold to display learner results and trigger adaptation review.
